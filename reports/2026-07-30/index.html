Vol. 009 - 30 July 2026 - Четверг
"Почему тут все еще старый выпуск?" - вопрос, который превратил статический сайт в GitHub Pages терапию.

Exhibit A

Сайт не застрял. Застрял источник.

`/today/` честно читал `reports.json`, находил запись за 2026-07-30 и открывал `/reports/2026-07-30/`. Проблема была хуже: сам файл за 30 июля был копией старого отчета из середины июля.

То есть механизм обновления был похож на календарь, который каждый день переворачивает страницу, но на всех страницах напечатан один и тот же вторник.

Exhibit B

Рутина писала в одно место. Домен смотрел в другое.

Рутина обновляла `getitcheappro/404909.xyz:roast/index.html`. А `roast.404909.xyz` жил в публичном `getitcheappro/roast-404909-xyz`, потому что приватный Pages на текущем плане GitHub отказался включаться с ошибкой 422.

Итог: приватная кухня готовит ужин, публичная витрина продолжает продавать вчерашний сухарь.

Публичный хост `getitcheappro/roast-404909-xyz` владеет `CNAME` и GitHub Pages для `roast.404909.xyz`.
Приватный источник `getitcheappro/404909.xyz` хранит daily source в `roast/index.html`.
Exhibit C

Duplicate Text Lab на `/roast/`

Отдельный сюрприз: `/roast/` отдавал не отчет, а Duplicate Text Lab. Workflow скачивал правильный private source, но при сборке Pages копировал в `_site/roast/index.html` корневой `index.html`.

Это уже не баг, это перформанс: роаст-сайт настолько устал быть роастом, что начал удалять дубли.

Exhibit D

Что было исправлено

Публичный workflow теперь забирает `roast/index.html` из приватного repo, архивирует его в `reports/YYYY-MM-DD/index.html`, обновляет `reports.json` и публикует Pages artifact.

Приватный repo получил dispatcher: когда рутина пушит новый `roast/index.html`, публичный deploy запускается автоматически. Рутину менять не пришлось. Секреты ушли в GitHub Actions secrets, а не в файлы.

`/` редиректит на `/today/`, а не притворяется Duplicate Lab.
`/roast/` теперь показывает fetched source report.
`/today/` показывает последний архив из `reports.json`.
`/history/` остается списком постоянных ссылок.
Final verdict

Виновен: старый source-файл

Приговор простой: сайт не был мертв, DNS не был главным злодеем, CDN не был главным подозреваемым. Главный баг - старый `roast/index.html`, который продолжал носить старый июльский заголовок и заражал каждый новый архив.

Сегодняшний фикс: заменить источник, пересобрать архив, проверить live URL. Если завтра снова всплывет старый выпуск, это уже не дата. Это диагноз.
